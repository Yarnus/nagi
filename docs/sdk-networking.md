# SDK 网络与协议

`nga-sdk` 是使用 Retrofit 和 OkHttp 的 Kotlin/JVM 库，负责请求映射、
会话处理和原生内容解析；Android 界面与持久化保留在 `app` 中。
当前接口签名见 `NgaClient.kt` 和 `Models.kt`。参考项目见 [致谢](../README.md#致谢)。

## 请求与会话

结构化读取使用表单编码的 POST，并带上 `__inchst=UTF8`。目录和社区请求
使用 JSON（`__output=8`）；主题和搜索优先使用 `lite=xml`，其次是紧凑 XML
（`__output=10`）。解析器也接受服务端返回的 JSON。帖子读取使用
WP 客户端请求头，其他结构化读取使用相应的 Apple 客户端请求头。
默认源站为 `bbs.nga.cn`；旧别名 `nga.178.com` 会解析到该源站。

解码遵循声明的 GB 系列字符集，否则先尝试严格 UTF-8，再尝试 GB18030。
XML 清理保留 Unicode 补充字符，并拒绝 DTD 和实体声明。
JavaScript 风格的封装仅作为数据解析，绝不执行。在交给 `org.json` 解析前，
为字符串外裸露的非负整数属性名加上引号；Android 解析器在这方面与
独立的 JSON-java 实现不同。

每次逻辑读取使用不可变的会话快照，在发送前和解析后检查。
账号修订号变化会使结果失效。凭据仅允许发送到白名单中精确匹配、使用
443 端口的 HTTPS 论坛源站，不得出现在 URL 或日志中。
不共享 Cookie 容器，也不缓存响应内容。

读取最多允许在官方 HTTPS 源站之间进行十次规范重定向，保留路径和查询参数。
拒绝包含用户信息、改变操作或路径、协议降级、非标准端口以及循环的重定向。
每次跳转都重新构造凭据：301/302/303 将 POST 改为 GET 并丢弃请求体；
307/308 保留请求体。写入不跟随重定向。

## 读取恢复

帖子读取始终使用选定的源站：

1. 先尝试 `lite=xml`，再尝试 `__output=10`。解析失败或响应体为空的 HTTP 错误
   会使当前读取客户端停用，并使用新的连接池重试另一种格式。
2. 对非空 HTTP 错误响应体进行解析，查找有效的结构化数据或明确的 NGA 错误。
   身份验证、访问受限和业务错误会终止恢复；传输失败和取消也一样。
3. 两种 XML 格式均失败时，仅当首次失败属于解析错误，才尝试原生 HTML。
   HTML 使用经过身份验证的表单 POST，不带 `lite`、`__output` 或 `noBBCode`；
   响应只用于解析，不在 WebView 中展示。HTML 失败后不再恢复。

只有成功恢复的 XML 格式才会成为该主题及作者筛选条件的首选格式；
HTML 永远不会成为首次尝试。整次读取共用一个截止时间。

其他读取可以在适用格式和已配置的官方备用源站之间恢复。
配置多种格式时，协议失败会推进到下一种格式；只有一种格式时立即停止。
连接、DNS 和套接字超时失败会跳过该主机上的其余格式；其他 I/O 失败可以
推进到下一种格式，但传输协议违规会终止恢复。
HTTP 5xx 会切换主机。身份验证、访问受限、业务错误和其他 HTTP 状态立即停止。
最多 512 项的提示映射仅保存源站和格式选择，不保存内容或凭据，也不用于路由写入。
更换读取客户端不会清空旧连接池或取消无关读取；传输使用 HTTP/1.1。

`timeoutSeconds` 覆盖所有恢复尝试。超过截止时间会转为类型化网络错误；
调用方取消仍以取消形式传播。错误区分为 `Network`、`Http`、`Authentication`、
`Restricted`、`Business` 和 `Protocol`。协议错误原因使用稳定代码，包含
XML/HTML 尝试链，不附带可能含有响应数据的原始解析原因或被抑制异常。

## 写入结果

所有写入使用独立、不会重试的传输，并有单次发送保护。
不进行主机或格式恢复、重定向或自动重放。

| 结果 | 含义 |
| --- | --- |
| `WriteResult.Confirmed` | HTTP 2xx，且未识别到 NGA 错误 |
| `WriteResult.Rejected` | 已识别的身份验证、访问受限或业务拒绝 |
| `WriteResult.Unconfirmed` | 其他传输失败或非 2xx 失败；调用方不得认定已拒绝，也不得自动重试 |

JSON、完成消息、XML 或 NGA HTML 错误标记中的已知错误优先于成功字段。
空白、格式错误或不熟悉的 2xx 响应体，以及完成代码、操作回显和跳转链接，
都不能单独作为拒绝接受写入的依据。不跟随跳转 URL，也不展示任意服务端文本。
这一策略可能将未识别的服务端失败视为已接受；接受写入不代表已证明持久化成功。
读取和发布准备仍使用严格解析。取消继续传播。

安全拒绝类别涵盖权限、禁言、频率限制、内容长度或过滤、验证、无效参数和重复提交。
未知原因保留为 `NgaRejectionReason.UNKNOWN`；这些异常不保留原始响应文本。
应用中的草稿和重放行为见[页面说明](design/screens.md)。

### 评分回执

`Confirmed.ratingReceipt` 是可选的。官方 `js_read.js` 的 `postScoreAdd`
结构使用 `data[1]` 表示分差，`data[2]` 的低四位分别表示移除的赞或踩（1/2）
以及最终的赞或踩（4/8）。忽略更高位。
`data[0]` 是展示文本，不是必需的成功提示语。

回执要求两个整数字段均存在，变化明确且与请求方向一致，并且分差等于最终投票值
减去移除的投票值。字段缺失或矛盾时不生成回执，但不改变写入是否被接受。
`PostRatingReceipt.currentRating == null` 表示取消投票；赞踩互切可能产生 ±2 分差。
没有有效回执时，使用方不得猜测分数变化。

### 诊断

`NgaConfig.writeDiagnostics` 默认为 false；普通 Android 调试版和发布版构建均保持关闭。
临时在调试版中开启后，可以在 `Rejected` 或 `Unconfirmed()` 上提供每次结果的安全元数据，
但不得使用全局的最后响应缓存或持久化日志。成功结果不附带诊断元数据。

允许的字段包括 HTTP 状态、固定的格式／类型／失败枚举、`data[0..2]`、
`error[0..2]` 和 `data.__MESSAGE[0/1/6]` 的类型，以及有界整数：
分差 −16..16、标志 0..255、消息状态或错误码 0..9999。
代码取自显式数字字段或简短的数字前缀。不包含凭据、响应体、URL、响应文本和任意键；
格式错误或越界的值保持缺省。

## 编辑已有帖子

`PublishAction.MODIFY` 使用 `post.php?action=modify`，并携带主题和帖子标识。
`preparePublish` 返回原始标题和 BBCode，校验目标与已认证响应中的身份，并要求内容字段存在。
纯文本编辑不需要附件上传的 `auth`；缺少编辑内容时，不能回退为空回复。

`publish` 以 `action=modify` 发送 `step=2`、`tid`、`pid`、标题和正文，
不带 `comment=1`。适用通用写入结果策略。编辑权限和时限由服务端决定；
客户端的所有权检查不能证明服务端允许编辑。

## 子板块可见性

`TopicPage.subforums` 默认为空。XML 的 `__F/sub_forums` 条目按位置提供
ID、名称、描述、筛选 ID 和属性。`item` 条目按版块导航，其他条目标签视为合集。
导航标识与筛选 ID 相互独立。跳过无效 ID 或名称；属性缺失或格式错误时禁用写入。

`Subforum.filterable` 要求筛选 ID 为数字，且属性值 >40。
`selected` 取决于属性值是否属于 `[7, 558, 542, 2606, 2590, 4654]`；
其他有效数字表示 false。这些兼容性表达式不能替换为位掩码。

`setSubforumVisibility(parentForumId, filterId, visible)` 向 `nuke.php`
发送经过身份验证的 POST：查询参数为 `__lib=user_option`、`__act=set`，
显示（SHOW）使用 `del=filterId`，屏蔽（BLOCK）使用 `add=filterId`；
表单为 `fid=parentForumId`、`type=1`、`info=add_to_block_tids`。
它修改账号的服务端偏好，而不是本地收藏。后续读取使用普通 `getTopics()`，
不带选中 ID 参数。
真实设置写入及跨客户端传播仍未验证。

## 通知与用户

`getNotificationFeed()` 使用 `raw=3`、`time_limit=0`，读取需要身份验证的
`noti/get_all`。`getNotifications(since)` 是列表适配器；接口默认的通知流
适配器不提供已知未读数。数字封装使用 `data[0].unread`，事件分组为
0（社区）和 1（私信）；事件标识包含分组、类型、参与者、目标和时间。

空通知响应还可能为 `data={"0":""}`；仅接受这一精确结构作为空列表，未提供的未读数保持未知。
任意非空字符串、`null`、数字或夹带未知字段的空字符串响应不视为空通知成功。

聚合未读数不能确定每条事件是否未读。仅有聚合数据的事件使用 `unreadKnown=false`；
包含具名记录时，仅当每条记录都有有效的显式已读标志，才生成计数。
标志格式错误意味着计数未知；分组格式错误仍是协议错误。SDK 不发送已读确认，
也不自行制定本地标为已读的策略；远端读取的副作用尚未确认。

资料字段将 `ipLoc`、正数且有界的 Unix 秒级时间戳 `regdate` 和字符串 `sign`
映射为可选的公开位置、注册日期和解析后的签名。缺失或无效的元数据省略；
UID 不匹配是协议错误。不推断完整 IP。

`getUserTopics(userId, page)` 使用 `thread.php`，携带 `authorid` 和 `page`，
缺少每页数量时按 35 项回退。`getUserReplies` 增加 `searchpost=1`，并保留
主题标识、帖子 ID、作者、日期和解析后的内容。缺少边界时 `hasMore` 可为空；
空页停止向前加载。两者都接受 XML/JSON，在发送前校验 UID 和页码，
并拒绝缺失或不匹配的回复标识。

## 帖子元数据与分页

帖子解析器提供净分数 `score`（回退为零）、可选的作者级别、威望、发帖数和客户端平台。
零分不能证明服务端提供了该值。级别先通过 `__GROUPS` 解析 `memberid`/`groupid`，
再尝试用户组文本。威望先取 `rvrc`，再取 `fame`：整数除以十，小数直接格式化。
无效或负数发帖数保持 null。客户端标签对 iOS/Android/Windows 及其数字代码
进行归一化；缺失标签省略，未知文本保留。
从 `commonui.postArg.proc` 提取 HTML 信息采用尽力而为的方式。
删除标记映射为 `TextSpan.strikethrough`，并可与下划线组合。

`PostPage` 提供服务端总数和每页数量。缺少每页数量时为零；端点专用的估计值
可用于顺序阅读，但不能支持精确跳楼或编造总数。HTML 首页可能省略 `__PAGE`。
缺少楼层，包括边界楼层，均属有效情况；不得要求返回数量或楼层与总数吻合，
包括按作者筛选的结果。没有分页信息就没有下一页。分页格式错误、后续页缺少元数据、
重复楼层和损坏的帖子标记仍是协议错误。不编造缺失内容。精确跳楼要求已知
每页数量和总数，并且结果未筛选；边界未知时仍允许输入页码和顺序阅读。

## 行内 NGA 表情

`NgaSmiles` 提供表情目录，共 265 项、七组。每项包含分组、名称、键、
规范 BBCode 和可信 HTTPS URL。`resolve` 支持默认别名 `1`、`:1`、`0:1`；
未知名称返回 null。运行时不执行站点脚本，也不内置表情图片。

`ContentBlock.Text.smiles` 保存相对于 `value` 的 UTF-16 区间，`value` 保留
原始代码，供复制、选择和样式偏移使用。附件仍使用 `ContentBlock.Image`。
BBCode 和 HTML 段落共用此表示；只有精确匹配可信且规范化的表情 URL，才能
确定表情身份。引用和折叠内容递归处理，代码保持原文，表格单元格仍是普通字符串。
表情请求不携带论坛凭据。

渲染和选择器行为属于[页面说明](design/screens.md)。
测试通过模拟请求提交代码正文；图片 GET 和合成草稿不能证明发帖兼容性。
成功解码动画图片不能证明其在真机上能持续播放 GIF。

## 测试

使用 [README](../README.md) 中的命令。模拟测试覆盖请求参数、恢复、错误、
凭据目标、取消、会话修订号、截止时间、格式错误的响应体、Unicode 和重放保护。
Android 的 `org.json` 行为除 JVM 测试外，还需要 Android 专项测试。
历史只读服务检查不能验证真实写入；自动化验证不得修改生产账号状态。
